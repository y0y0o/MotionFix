## 5. 评估样本扩充(50 → 200)—— 本次主要工作

### 5.1 为什么做

评估每生成器 n=50 偏小。目标:重新在 HumanML3D 测试集另选 150 个 prompt,让三个生成器
各自重新生成,把评估样本扩到 ~200,以增强统计强度(回应导师"证据不够强"的总批评)。

### 5.2 prompt 选择(所有生成器共用)

**怎么做**:`data/test_inputs/_expand/prompts_150.txt` —— 从 `HumanML3D/test.txt` 选 150 个
不与现有 50 条重叠、且本地有 GT 的测试 ID(带 GT 以后还能补 FID 参考集)。三生成器共用同一批
prompt,评估各自独立(不等 n 统计上成立)。

### 5.3 T2M-GPT:50 → 200 ✅ 成功

**怎么做**:
- 找到原始 50 条的生成脚本 `T2M-GPT/generate_t2mgpt_batch50.py` 作模板,写
  `T2M-GPT/generate_t2mgpt_expand.py`:CLIP 编码文本 → `trans.sample` → `vqvae.forward_decoder`
  得到 (1,T,263) → **去归一化**(用 `mdm/dataset/t2m_mean/std`,与原 50 条一致)→
  `recover_from_ric(22)` → (T,22,3) → 存入 `t2mgpt_raw_joints/`。
- SLURM 提交(`t2mgpt` 环境,`--gres=gpu:pascal:1`);VQ 采样快,几分钟跑完。

**验证/结果**:150 条全部 (T,22,3)、0 NaN、footV_mean 0.016(比旧样本 0.032 更平滑)、0 异常。
**T2M-GPT 干净扩到 200。**

### 5.4 MDM:失败,已回退到 50 ❌(完整排障记录)

MDM 折腾最久,值得完整记录,因为踩了多个坑。

**背景**:MDM 用 `mdm/sample/generate.py`(扩散采样),权重
`model000200000.pt` / `model000600000.pt`,输出 `results.npy`(N,22,3,T)。

**排障过程(逐步逼近根因)**:
1. **第一次(200k,无 `--use_ema`)** → 生成的样本无 NaN 但脚速是正常值的 **~10×**、脚飞到 2.5m、
   穿地。原因:checkpoint 里有 `model`(原始)和 `model_avg`(EMA 平均)两套权重,
   `load_saved_model(use_avg=args.use_ema)` 决定用哪套;不加 `--use_ema` 就加载了**未平均的原始权重**
   → 抖动垃圾。
2. **加 `--use_ema`,但 batch=50** → 仍崩坏(NaN / 飞脚)。原因:**batch 级数值不稳定**——
   同样 10 个 prompt 单独 batch=10 是好的,塞进 batch=50 就变垃圾。
3. **`--use_ema` + batch=10** → 位置正常了(footY 合理),**但脚滑 FSR ~94%**(原始 50 条 ~12%)——
   脚看着贴地却在接触时持续打滑,与原始**不同质,不可用**。仍有未查明的生成配方差异
   (guidance / 接触后处理 / 变体)。
4. **600k + `--use_ema`** → 段错误硬崩溃(exit 139,无输出)。
5. **基础设施 flaky**:每次 `sample.generate` 都要把整个 t2m 数据集读进内存,gpu3 节点在此阶段
   **频繁段错误 / 挂起**(一次补跑挂了 2h21m,0 收获,已取消)。yield 不可靠(15 批只活 5 批)。

**结论**:MDM 在本环境**无法复现原始 50 条的质量**,回退到原始 50。
(补充:mp4 可视化步骤总会段错误 exit 134/139,但 `results.npy` 在崩溃前已存,无妨。)

**踩坑已存进项目记忆** `mdm-generation-gotchas`:生成 MDM 必须 `--use_ema` + batch≤10,且仍可能质量不达标。

### 5.6 重跑评估 + 核心结论

扩样本后重跑五路消融(`testing/v19_eval.py` 对 t2mgpt;`testing/momask_pool_eval.py` 对 momask pooled)。

**T2M-GPT(n=50→200)FSR:**
```
             n=50    n=200
original    11.99%   6.43%
deskate_ik   6.65%   3.98%   ← 降幅最大
gauss_ik     8.83%   4.92%
learn_ik    10.99%   6.00%
v19_ik       8.93%   5.08%
平滑相对deskate(n=200): gauss +0.94 | learn +2.02 | v19 +1.10
```

**MoMask(n=10/50→200 pooled)FSR:**
```
             n=10旧   n=200
original    16.29%   7.86%
deskate_ik   8.18%   4.73%   ← 降幅最大
gauss_ik    11.12%   6.33%
learn_ik    12.85%   7.18%
v19_ik      11.63%   6.57%
平滑相对deskate(n=200): gauss +1.60 | learn +2.45 | v19 +1.85
```

**三条核心结论在两个生成器的 4× 样本下全部保住**:
1. **物理去滑主导降 FSR**(original→deskate 降幅最大);
2. **平滑器对 FSR 做负功**(相对 deskate 全为正:+0.9~+2.5pp);
3. **v19 ≈ 调好的高斯**(v19 与 gauss 接近,学习无稳定优势)。

**重要 caveat(必须写进论文)**:两个生成器的绝对 FSR 都比原来低(如 MoMask 16%→8%),
是因为新 150 个 prompt 更广更平(原 50 条偏脚滑高发的走/转/旋转类)。所以 n=200 是
**在更广、更有代表性的样本上复核了结论**,不是同分布收紧估计。

## 6. 感知实验:工具全部搭好(等人类数据)

### 6.1 为什么做

导师第 7 点"physical plausibility"还差**用人验证**那半;整条 FSR–Jitter 权衡叙事底下压着
一个未验证假设:"Jitter 低 = 看起来更自然"。感知实验一箭双雕。

### 6.2 设计

- **2AFC 成对强制选择**:并排两段无标签视频,问"哪个更自然"。
- **12 动作**:10 个 FSR 5–29%(修正有可见作用)+ 2 个 FSR 0%(注意力对照)。
  选自 `data/test_inputs/_expand/perceptual_ids.txt`(按 FSR 铺开,避开 0% 全废对)。
- **3 类盲配对**,每类拿交付点 v19 和另一方比:`orig vs v19`、`deskate vs v19`、`gauss vs v19`。
  = 36 对/人,≈10 人。
- 网页自动打乱对序 + 随机左右,消除位置/顺序偏差。

### 6.3 怎么做的(工具链)

- **刺激渲染** `utils/render_perceptual.py`:每动作每条件渲一段**单条件、无标签、统一机位**的 mp4
  (共享坐标轴范围保证同动作 4 条件可比),中性骨架(不高亮脚,避免诱导)。
  → `outputs/perceptual/clips/<mid>_<cond>.mp4`,共 **48 段**(校验齐全、0 损坏)。
- **打分网页** `outputs/perceptual/rating.html`:自包含 HTML,浏览器双击打开,逐对看→选
  (←A / 空格分不清 / →B),导出 `perceptual_<代号>.csv`。
- **分析脚本** `analysis/perceptual_analysis.py`:三类对比的 v19 偏好率 + 二项检验 + 对照动作注意力检查。
- **说明** `outputs/perceptual/README.md`。

### 6.4 怎么跑(交给用户的三步)

1. 双击 `outputs/perceptual/rating.html`(不需服务器);
2. 找 ≈10 人各做一遍,导出 CSV;
3. CSV 收进 `outputs/perceptual/responses/`,跑 `python analysis/perceptual_analysis.py`。

### 6.5 结果怎么读

- **`deskate vs v19` 不显著** → 学习平滑器无可感知优势 → 支持"学习不必需"主结论,甚至可交付纯物理 deskate_ik;
- **`orig vs v19` 中 v19 显著更自然** → 修正有效的人证;
- 对照动作(FSR=0)应接近平局,用于剔除不认真的打分。
