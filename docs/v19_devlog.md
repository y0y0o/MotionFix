## 0. 本轮要修什么

2026-07-20 代码审查在 V18+IK 上定位到 13 个问题(见 `version_review_20260720.md` §6.2)。
本轮按性价比处理其中 6 个,分两类:

**A 类 — 方法本身的缺陷**
- **A1** 2骨IK 不在训练回路里:训练在 IK 之前算 loss,评测在 IK 之后测指标
- **A3** loss 没有要求「分区行为」:平滑器能看到接触权重(高斯看不到),这是它唯一的
  结构性优势,而 `mean(|v|·w³)` 这个均值代理从未要求它兑现

**B 类 — 实验设计的缺陷(导致无法判断 A 类问题)**
- **B1** MoMask 评测 50 条里 40 条是训练过的
- **B2** `deskate_ik`(FSR 最好的配置)不在跨生成器主表里
- **B3** 按训练 loss 存 checkpoint,无验证集
- **B6** edge-padding 稀释梯度

## 2. [A1] 量化 IK 错配 —— 训练和评测优化的不是同一个东西

`training/v18_ik.py` 全文没有 `apply_ik`;`testing/v18ik_scale.py:95` 则是
`apply_ik(m, smooth_fix(...))`。平滑器从未见过 IK。

实测(10 条 held-out,平滑器输出 vs IK 之后):

```
           平滑器输出      IK 之后
FSR         12.0%    →    12.9%      (+0.8pp)
Jitter     0.00970   →   0.01143     (×1.18)

踝 XZ 最大位移最严重的动作:
  p004311_complex  0.50m    p012498_complex  0.40m
  p012883_dance    0.37m    p002530_walking  0.32m
```

学习器输给高斯 1.8pp,而**IK 这一级自己就吃掉 0.8pp**——接近一半的差距来自一个
模型从未被训练穿过的阶段。受影响最重的是 rotation / complex / dance,
**正是导师说 "rotational motions gains limited" 的那一类**。

### 实现

`models/v19.py::torch_ankle_ik` —— 可微版 IK。

关键简化:**只有踝关节路径需要可微**。FSR 只定义在踝(7,8)上;`apply_ik` 里
`toe_new = ankle_new + (toe-ankle)_orig` 是刚性跟随;余弦定理解膝盖不碰任何指标。
所以训练图里只需复刻「水平 reach clamp + 径向 clamp」两步。

自测(`python -m models.v19`):
```
torch vs numpy IK ankle — max abs diff: 2.220e-16
gradients finite ✓
```
**与 numpy 版在机器精度上完全一致。**

### 顺带发现的第三处错配

- `compute_fsr` 只用**踝 (7,8)** = 4 维
- `compute_jitter` 用**全部四个脚关节 (7,8,10,11)** = 8 维
- 但 `apply_ik` 用刚性跟随**覆盖掉脚趾**

→ V18 的平滑器输出 8 维,其中 4 维(脚趾)在 IK 阶段被丢弃。
**一半的模型容量和一半的 loss 梯度花在了永远到不了指标的输出上。**
V19 改为只输出踝 XZ 4 维(46,276 参数 vs V18 的 48,840)。

## 3. [数据] 发现 `data/prep/v14.py` 的反归一化 bug

原计划把训练集从 40 条 MoMask 扩到数千条 HumanML3D(`data/training/v14/target_*.npy`,
15980 条已转换好的动作)。第一次训练时 loss 的基线值明显异常,回查数据:

```
                        脚Y动态范围      被判为「接触」的帧
v14 target(反归一化)      0.090 m        96% 的动作 >0.8
raw(正确)                0.269 m        31% 落在健康的 0.3-0.8 区间
MoMask(参考)             0.439 m        52% 落在 0.3-0.8
```

根因:`data/prep/v14.py::convert_to_joints` 对 `HumanML3D/new_joint_vecs` 做了
`motion_263 * std + mean`,但**这批文件本身就是未归一化的原始特征**,多做一次
反归一化把脚部垂直动态压进了 9cm 的带里。

后果:接触启发式(ground = 脚Y的5分位数)把几乎每一帧都判成接触 →
`deskated_target` 把一整条行走轨迹 plant 在单个均值点上 → 去滑目标偏离原始 **0.65m**
(MoMask 上只有 0.042m)。

> ⚠️ **这条要写进论文的 threats to validity:V14 和 V15 都用了这份被污染的语料。**
> 两者都退化成恒等映射。恒等坍缩另有解释(L1 信号被 88% 不变维度冲淡),
> 但**训练数据同时也是坏的**,所以这两个负面结果是**混淆的**,
> 不能当作「学习在这里行不通」的干净证据。

修复:新建 `data/prep/v19.py`,直接读 `new_joint_vecs`、**不做反归一化**,并按
接触帧占比 ∈ [0.2, 0.9] 过滤(区间外接触启发式无意义)。

```
kept 4000 motions
rejected: 太短 291 | 接触占比越界 2844 | 去滑偏差 >0.3m 2
去滑偏差(保留的): mean 0.0317 m     (MoMask 参考 ~0.042 m)   ← 正常了
```

## 4. [A3] 第一次训练:模型退化成恒等 —— 而这是个**有信息的**失败

`models/v19.py::V19Loss` 按分区行为重写:
```
L = λ_air   · acc² 按 (1-w) 加权        ← 空中猛平滑
  + λ_all   · acc² 不加权                ← 保持边界连续
  + λ_skate · soft_count(|v| > 0.03) 在接触帧   ← 对齐 FSR 阈值语义,不是均值
  + λ_anch  · |out - deskated|           ← 防漂移 / 防作弊
```
λ 由**每项梯度范数**自动标定(B5),验证集选点(B3),mask 归一化(B6),
训练语料 4000 条 HumanML3D(B7 → MoMask/MDM/T2M-GPT 全部 out-of-distribution,
**泄漏在结构上不可能存在**)。

300 epoch 结果:
```
ep     train       val      jit_air     skate     anch    FootErr
  1   0.00824   0.00814   3.19e-03    0.0677   0.0155    0.0543
300   0.00809   0.00800   3.18e-03    0.0677   0.0143    0.0538
```
`skate` 300 个 epoch **一位小数都没动**,`anch` 反而在降。诊断:

```
训练后残差 |res| mean = 6.287e-10        ← 模型完全退化成恒等
IK clamp 生效帧占比 = 16.5%
接触帧速度分布: 中位数 0.00000, p80 = 0.00000, p90 = 0.01311, p95 = 0.04901
sigmoid 未饱和: tau=0.008 时 96.3% 的帧有有效梯度
```

**梯度是活的,是 residual=0 在这组权重下真的就是最优解。** 原因:

1. **去滑后 80% 的接触帧速度已精确为 0**(planted 成常数段)。skate 项无从改善,
   任何平滑只会把运动扩散进这些零速度区间 → skate 变差。
2. **空中帧的轨迹就是原始轨迹**(去滑只改接触段),本来就平滑 → `jit_air` 无从改善
   (卡在 3.18e-3)。
3. 真正的抖动全在 **plant→air 边界**上,而唯一奖励平滑边界的 `jit_all`
   权重最低(share 0.15)。

> **结论:λ 配比不是一个要「调对」的超参,它是选择 FSR–Jitter 前沿上工作点的旋钮。**
> 我给 skate 的份额(0.35)把最优解推到了纯去滑那一端。
> 正确的实验不是取一个点,而是**扫这条前沿**,并与高斯的前沿叠在一起比。

于是给 `training/v19.py` 加了 `--jit-share` 旋钮,扫 6 个工作点。

## 5. [严重] 第一次扫描全部无效 —— 学习率 2e-3 让模型坍缩回恒等

加了 `--jit-share` 旋钮后扫 6 个点,val loss 看起来漂亮地单调下降:
```
js=0.45  0.00800    js=0.70  0.00550    js=0.79  0.00494
js=0.60  0.00629    js=0.76  0.00511
```
但跨生成器评测出来,**六个点的 FSR/Jitter 与 `deskate_ik` 完全相同,到 5 位有效数字**。

追查:
```
[js=045] 推理残差 |res| mean=9.5e-09      训练缓存上残差 9.5e-09
[js=079] 推理残差 |res| mean=1.2e-08      训练缓存上残差 1.2e-08
```
**残差恒为 0。val loss 的下降完全是换 λ 权重造成的假象,不是学习。**

逐步抓梯度:
```
step  0 loss=0.011960 grad(末层)=7.1e-03 grad(首层)=0.0e+00 |res|=0.0e+00
step  1 loss=0.023082 grad(末层)=2.9e-01 grad(首层)=1.7e-02 |res|=1.6e-02   ← loss 涨了一倍
step 11 loss=0.012270 grad(末层)=1.4e-05 grad(首层)=6.0e-06 |res|=4.3e-04   ← 被拉回 0
```
Adam 第一步冲过头(末层零初始化 ⇒ 二阶矩为 0 ⇒ 首步幅度 = LR),loss 恶化一倍,
之后被拉回 residual=0 且梯度衰减。

### 决定性检验:在我的 loss 下,高斯的解到底更好还是更差?

如果高斯解的 loss 更低,说明是**优化失败**;如果更高,说明**我的 loss 写错了**。

```
方案            jit_air     jit_all     skate     anch
res=0 (去滑)   3.773e-03  1.243e-02   0.0717   0.0149
高斯 σ=0.8     1.252e-03  3.980e-03   0.0816   0.0259
高斯 σ=1.5     6.336e-04  1.716e-03   0.0964   0.0428
高斯 σ=2.6     3.501e-04  8.602e-04   0.1263   0.0767
```
**高斯解在 jitter 两项上好 6–7 倍。loss 是对的,是优化失败了。**

对照实验(js=0.79 的 λ,res=0 总 loss = 0.005158):
```
零初始化   lr=2e-3    best=0.005158  ✗ 没打败    |res|=1.0e-04
零初始化   lr=2e-4    best=0.003573  ✓ 打败      |res|=1.6e-03
小随机初始 lr=2e-4    best=0.003633  ✓ 打败      |res|=1.7e-03
小随机初始 lr=5e-5    best=0.004703  ✓ 打败      |res|=5.6e-04
```

> **根因:LR 2e-3 太高。** 改 2e-4 后重扫。
> 教训:**「val loss 在下降」不等于「模型在学习」——换了权重的 loss 之间不可比。**
> 下次任何 loss 曲线都要配一个与权重无关的量(这里是 |residual|)一起看。

## 6. [前沿扫描] 最终结果

学习率修正后重扫 6 点,并额外补 2 点(降低 anchor 份额)把前沿延伸到低 jitter 区
—— 因为原扫描把 `anch` 固定在 0.20,这是**我自己引入的混淆**:V19 到不了低 jitter
区可能只是锚点太强,而不是方法的限制。补点后确认两者都有影响。

完整结果、逐点对比与结论见 **`docs/v19_results.md`**,图见 `analysis/v19/frontier.png`。

一句话:**修完六个缺陷后,学习式平滑器仍然没有打赢调好的高斯**——24 个可比工作点
里只赢 3 个(每生成器 1 个,且都在残差最小的一端)。但 V19 显著优于 V18,
说明 V18 与高斯的差距**有相当一部分是训练缺陷而非「学习不行」**。

## 8. 追加(同日):语义评估 + 抖动性质

用户要求「按你自己的建议继续做」,于是补了 §6 里列的两项。

### 8.1 语义保真评估 —— 需要先造一个 joints -> 263 的正向转换

评估器吃 263 维特征,MotionFix 输出 (T,22,3) 关节位置,而 `recover_from_ric` 只有反向。
从 `HumanML3D/motion_representation.ipynb` 抽出 `process_file` + `uniform_skeleton`
成 `utils/joints_to_feats.py`。

**方法学上的关键判断**:这个转换**不是** `recover_from_ric` 的精确逆(6D 旋转靠 IK 重推、
骨架重新 uniform、重新落地)。但原始、修正、GT **全部走同一条管线**,误差是共模的,
所以**差值**有效、**绝对值**不可与论文对比。这一点必须在论文里写清楚。

踩到的三个坑:
1. `HumanML3D/common/quaternion.py:13` 用了 NumPy 1.24 已删除的 `np.float`
   → 在导入前加兼容垫片(不改外部仓库)。
2. motionfix 和 T2M-GPT 都有 `utils`/`models` 包 → 分两阶段执行:先在 motionfix 上下文
   算完所有 263 特征,再清 `sys.modules` 切到 T2M-GPT 上下文跑评估器。
3. `TextEncoderBiGRUCo` 用 `pack_padded_sequence(enforce_sorted=True)`,**cap_lens 必须降序**
   (参考 `collate_fn` 正是按它降序排的);运动编码器用 `enforce_sorted=False` 不需要。
   → 排序后嵌入、再用逆置换还原顺序。

**加了配对 bootstrap 显著性检验**,否则 n=50 的表格没有说服力。结果:12 个组合里只有 3 个
达到显著。**「不显著」是功效不足,不是阴性证据** —— 文档里明确写了。

### 8.2 抖动性质 —— 推翻了我自己前一小时的交付建议

`docs/v19_results.md` 原本推荐 `v19_045`(FSR 最低)。但抽搐是**尖峰**现象,Jitter 的 RMS
看不出来。加了 p99/max/尖峰率:

```
            RMS      p99      max    p99/原始 max/原始
original  0.02289  0.06560  0.07825   1.00x   1.00x
v19_045   0.02882  0.10097  0.13982   1.54x   1.79x   ← 尖峰大幅变大
v19_088a10 0.02072 0.05972  0.07389   0.91x   0.94x   ← 比原始还平
deskate_ik 0.04600 0.19819  0.28468   3.02x   3.64x
```

**交付点改为 `v19_088a10`**,它在 FSR / Jitter RMS / 尖峰 / 语义四项上全部优于原始。

> **教训:标量指标会掩盖它自己声称在测的现象。** Jitter 的 RMS 是为了代表「抽搐」而设的,
> 但抽搐是尾部事件,RMS 是二阶矩的平均 —— 两者在这里给出了相反的排序。
> 这与 §5 「val loss 下降 ≠ 模型在学习」是同一类错误的两个实例。

### 8.3 视频

`utils/render_v19.py` 出四联画(Original | De-skate+IK | Gaussian+IK | V19+IK),
已渲染 001120 / 000818 / 012498。**注意这三个渲染的是旧交付点 v19_045。**
我能量化尖峰,但**看不了视频,视觉判断必须由用户做** —— 这一点没有代劳。
