## 0. 三十秒速览

**问题**:VQ 类文生动作模型(MoMask / T2M-GPT)比扩散模型快 15–20×,但脚会「打滑」(foot skating)——该踩住地面时脚在地上滑。

**你的定位**:**后处理**修正。不重训生成器,在输出的 `(T, 22, 3)` 关节序列上做修复,且要能跨生成器通用。

**最终方法(V18 + IK)**:
```
输入 → 去滑(物理) → 学习式平滑器 → 2骨IK(物理) → 输出
      接触段 plant     48.8K 1D-CNN     髋→膝→踝 + 刚性脚趾
      在 XZ 均值        磨圆 plant→air    钳制到腿可达范围
      (低 FSR,无漂移)   边界(低 Jitter)   (骨长刚性)
```

**一句话贯穿全局的教训**:
> 脚滑修正本质是**约束满足问题**(接触时脚速=0),不是学习问题。
> 纯学习方案试了 5 次全败——要么信号被冲淡退化成恒等映射,要么钻可微代理的空子。
> 最终能用的方案里,**降 FSR 的部分全是物理规则,学习只负责降 Jitter**。

## 1. 问题定义与评估框架

### 1.1 数据格式
- 所有模型操作 **22 关节、3D 世界坐标**,`(T, 22, 3)`,展平为 `(T, 66)`
- 脚部关节:**7, 8(踝)、10, 11(脚趾)**
- FSR 定义在**踝关节**上 → 想降 FSR 就必须移动踝 → 必然牵动小腿(这是后来「扯腿」问题的根源)

### 1.2 七指标(`utils/metrics.py`)

| # | 指标 | 含义 | 关键阈值 |
|---|------|------|---------|
| 1 | **FSR** | 接触帧中水平速度 > 阈值的**帧占比** | `skate_thresh = 0.03` m/frame |
| 2 | **Jitter** | 脚部加速度 RMS | — |
| 3 | Floating | 接触标签帧中脚实际悬空的比例 | `h_thresh = 0.05` m |
| 4 | FootErr | 修复后 vs 原始的脚部平均位移 | — |
| 5 | BoneCV | 骨长变异系数(时间稳定性) | — |
| 6 | Penetration | 脚穿透地面深度 | — |
| 7 | ContactAcc | 接触标签保持率 | `v_thresh = 0.5` m/frame |

**接触判定**:`脚高 < ground + 0.05` 且 `水平速度 < 0.5`,其中 `ground` 取该动作该关节 Y 的 **5 分位数**。

**学术对标**:真实动作 FSR 0.0%,MaskControl/OmniControl(ICCV 2025)5.5%,MoMask ~14.1%,MDM 10.2%,PriorMDM 9.0%。

> ⚠️ **注意**:FSR 是一个**计数/比例**指标(超阈值的帧数占比),不是均值。这一点在后面 §6.2 会成为关键。

## 3. 五次纯学习尝试的失败(V8 / V14 / V15 / V16 及变体)

这是整个项目**最有价值的部分**,因为它是系统性的否定证据。

### 3.1 V8 — Transformer + 选择性脚部替换

**架构**(19.1M 参数,后续 V11–V15 全部沿用):
```
(T,66) → Linear(66→512) → PositionalEncoding(sin) → TransformerEncoder ×6
       (d_model=512, nhead=8, FFN=2048, dropout=0.1)
       → Linear(512→256) → ReLU → Linear(256→66)
```

**核心机制 `_selective_replace`**(V8 唯一真正起作用的东西):
1. 逐帧判定:`脚高 < ground+5cm` 且 `水平速度 > 0.03` → 判为滑步
2. 只在这些帧混合:`output = 0.5·original + 0.5·predicted`
3. 非脚关节、非滑步帧:**完全不动**(硬约束)

**损失**:
```
L = L1(全身) + 0.5·L1(全身速度) + 2.0·L1(脚位置) + 2.0·L1(脚速度)
```

**结果**:FSR 14.1% → **15.6%(变差)**,Jitter 0.0128 → 0.0278(×2.2)

> ⚠️ **文档冲突提醒**:`CLAUDE.md` 里写 V8 是「~2.9% FSR reduction」,但 `research_log` 记录的坐标修复版 V8_new 是 14.1%→15.6%(变差)。**这两个数字对不上**,复习时以 research_log 的实测为准,并且这处矛盾需要你确认后统一。

### 3.2 V9–V13 — 在 V8 架构上的五轮修补

| 版本 | 想解决什么 | 加了什么 | 为什么没成 |
|------|-----------|---------|-----------|
| V9 | 抽搐 + 只改脚不改腿 | 软门控、时序平滑、骨链 IK | 不稳定,导师明确指出 "not yet stable" |
| V10 | 对标 FRDM 论文 | 接触门控 L_Foot、L_Smooth、速度一致性;训练=推理一致(去掉 selective replace) | **去掉 selective_replace 后直接退化成恒等映射** |
| V11 | 救 V10 | 恢复 selective replace + 重新平衡权重(修正力 > 保守力) | 仍不足 |
| V12 | 位置跳变 | 双头(位置+位移)、ε-不敏感损失、窗口扩张、速度门控防 4m 瞬移 | 复杂度上去了,指标没上去 |
| V13 | 修正幅度太小 | 训练噪声放大 3–5× | 无效 |

**V10 的教训最重要**:`selective_replace` 这个**推理期硬约束**才是 V8 能工作的原因,不是网络学到了什么。一旦拿掉,保守损失(L_smooth、L_upper_vel)压过修正损失,模型立刻退化。

### 3.3 V14 — 定向脚滑模拟(失败)

**思路**:V8 训的是「随机噪声→干净」(泛泛去噪),V14 改成「脚滑→干净」(定向)。

**数据**(`data/prep/v14.py`):
- HumanML3D 8177 条 → 只在脚关节 [7,8,10,11]、只在 XZ、只在接触段加平滑滑移
- 非脚关节 / Y 轴 / 非接触帧:**零改动**(已验证 max diff = 0.0000000000)
- 产出 **15980 训练对**(7990 motion × 2 增广)

**结果**:FSR 15.6%(没改善),Jitter ×2.2。Alpha sweep(0.1/0.5/0.9/1.0)全线无效。

> 💡 **这里有一条现在仍然重要的信息:V14 的数据管线能产出 15980 个训练对,基础设施是现成的。** 而当前 V18+IK 只用了 40 条 MoMask。

### 3.4 Physics —— 唯一真正降 FSR 的东西(纯规则,无模型)

`utils/physics_fix.py`:接触帧(脚高 < ground+5cm)且水平速度 > 阈值时,把超出的速度阻尼掉。`damp_factor=0.0` = 压到刚好等于阈值。

**damp sweep(50 条 MoMask)**:
```
Version           FSR     Jitter   FtErr   ContactAcc  BoneCV
Original          14.1%   0.0128   —       —           —
Physics damp=0.0   9.5%   0.0347   0.0157  99.9%       0.0332   ← 最佳
Physics damp=0.1  16.8%   0.0318   0.0141  99.9%       0.0303
Physics damp=0.3  19.6%   0.0173   0.0081  100.0%      0.0247
```
**41/50 改善,1 恶化(p009958 倒退行走 +4.5pp),8 不变。**
**代价:Jitter ×2.7**(硬冻结脚 → 边界跳变)。

### 3.5 V15 — 物理教师蒸馏(失败:退化为恒等)

**思路**:Physics 的输出就是「正确答案」,拿它当 teacher 做监督学习。
- 50 motion → 40 训练 / 10 held-out,5× 增广 = **200 训练对**

**结果**:
```
              FSR      Jitter    FootErr   BoneCV
Original     16.3%     0.0140    0.0000    0.0050
Physics      11.9%     0.0319    0.0140    0.0310   ← 教师
V15          18.2%     0.0169    0.0038    0.0119   ← 学生
```
**FootErr 仅 4mm = 模型学成了恒等映射。**

**根因**:L1-to-target 损失被 **88% 应保持不变的维度**主导 → 脚-XZ-接触帧的梯度信号被冲淡 → 输出「什么都不改」就是 loss 最低解。

### 3.6 V16 — 自监督抗作弊损失(失败:钻代理空子)⚠️ 重点

**思路**:彻底放弃 L1-to-target,**直接优化目标**,无需 target:
```
Loss = λ_skate·soft_FSR + λ_smooth·jitter + λ_anchor·‖foot-input‖ + λ_preserve·‖nonfoot/Y-input‖
权重: skate=10,  smooth=5,  anchor=2,  preserve=20
```
设计意图很好:soft_FSR 与 jitter 互相拉扯,逼模型**渐进减速**而不是硬冻结(抗抽搐)。

**训练**:四个分量全部同步下降(skate ↓8×)。**看起来完美。**

**测试(10 held-out)**:
```
              FSR      Jitter    FootErr
Original     16.3%     0.0140    —
V16 full     35.8%     0.0056    0.12–0.25m   ← 模型原始输出
V16 blend    17.9%     0.0266    —            ← 50% blend 掩盖了灾难
```

**模型输出了一条全新的、超级平滑的轨迹**:Jitter 0.0056 满足 smooth 项,速度适中满足 soft_skate 项——**但脚跑到 12–25cm 之外,真实 FSR 35.8%,比原版差一倍。**

> 🔴 **这条教训在今天依然生效,必须记住:可微 soft-FSR ≠ 硬 FSR,模型会利用这个缝隙。**
> 这正是你最初担心的「为了更小的值出现不符合实际的效果」,发生在**代理指标 vs 真实指标**这一层。

### 3.7 五次失败的规律

| 方案 | 范式 | FSR | 失败原因 |
|------|------|-----|---------|
| V8 | L1 模拟噪声 | 15.6% ❌ | 信号冲淡 → 恒等映射 |
| V14 | L1 模拟脚滑 | 15.6% ❌ | 同上 |
| V15 | L1 物理教师 | 18.2% ❌ | 88% 维度答案是"不改" → 恒等映射 |
| V16 | 自监督代理损失 | 35.8% ❌ | 钻代理与真实指标的空子 |
| **Physics** | **纯规则** | **9.5%** ✅ | **直接操作真实量,无法作弊** |

## 5. V17 → V18 → V18+IK:最终方法的形成

### 5.1 V17 — 物理 + 学习平滑器(部分成功,揭示根本对抗)

**设计**:
- Stage 1 物理修正(damp=0.0)→ FSR 降低
- Stage 2 轻量 1D-CNN 平滑器,预测脚 XZ 残差,磨平物理造成的突变

**结果(10 held-out)**:
```
Metric      Original    Physics     Hybrid(V17)
FSR ↓       16.3%       11.9%       20.2%    ← 比原版还差!
Jitter ↓    0.0140      0.0319      0.0244
```

平滑器确实降了 Jitter(0.0319→0.0244,-24%),**但把冻结的接触段又抹出了速度,FSR 涨到 20.2%**。

**🔑 由此得出全项目的核心矛盾**:
```
低 FSR  → 接触时脚速→0 → 平段 + 硬边界 → 抖动高
低抖动  → 脚速度平滑     → 接触时脚在动 → FSR 高
```
在**位置空间**直接改脚,这个对抗无解。

### 5.2 V18 — 速度空间突破 ⚠️(注意:这个版本最终被放弃了)

**核心洞察**:不要直接改位置,而是**预测速度场 → 把接触帧速度 mask 掉 → 积分还原位置**。

```
原始脚 XZ 位置 → v_orig = diff(位置)
                      ↓
        v_pred = v_orig + model_residual   (residual 零初始化)
                      ↓
        v_masked = (1 - w) · v_pred        ← 接触帧 w≈1 → 速度×0 → 脚不滑
                      ↓
        pos_new = pos[0] + cumsum(v_masked) ← 积分,位置天然连续
```

**为什么能同时降两个指标**:
- FSR:`(1-w)` 在接触帧≈0,把脚速结构性压到 0 → **保证低,非学习、不可作弊**
- Jitter:`w` 是 soft sigmoid,速度在落地前几帧就**平滑地**降到 0(不是硬切)→ 边界连续
- 位置连续:cumsum 出来的位置天生连续,无 V17 的跳变

**结果 —— 指标层面确实突破了**:
```
Metric      Original   Physics   Analytical(res=0)   V18(learn)
FSR ↓       16.3%      11.9%     3.7%                5.8%
Jitter ↓    0.0140     0.0319    0.0123              0.0132
FootErr ↓   0.0000     0.0140    0.3812              0.3956   ← 漂移 38–40cm!
BoneCV ↓    0.0050     0.0310    0.0555              0.0673
```
**FSR 5.8%(≈SOTA 5.5%)+ Jitter 0.0132(低于原始)—— V8–V17 从未做到。**

**但两个致命问题**:

**(a) 积分漂移 38cm。** 每个接触段脚 plant 在入口位置,原始滑到出口,缺口 δ = 滑动距离;空中从「落后」的位置出发摆动 → **缺口逐周期累积**。

首次修复尝试失败的原因值得记住:fidelity 损失写成了 air-weighted `(1-w)`,**把接触帧 mask 掉了**——但漂移恰恰发生在接触帧。训练 fidelity 降到 0.05(只是空中的),测试 FootErr 仍 0.40m。**训练损失和测试指标之间的巨大 gap 就是这个 bug 的证据。**

**(b) 扯断小腿。** 小腿(膝4→踝7)原长恒定 0.40m:
```
动作            原长      V18后均值   最大拉伸
p000021 旋转    0.40m     0.998m     2.05m   ← 拉长 2 米!
p000818 旋转    0.40m     0.890m     0.92m
p012498 复杂    0.40m     0.498m     0.31m
p002530 走路    0.40m     0.398m     0.07m
p001120 走路    0.40m     0.407m     0.09m
```
> **根本结论**:FSR 定义在踝关节,要降 FSR 必须移动踝 → 必然牵动小腿。走路类主要在摆动相,plant 偏移小(7cm)尚可;**旋转类脚持续移动,plant 累积偏移巨大 → 视觉崩坏**。
> **这正好解释了导师观察到的 "rotational motions gains limited"。**

### 5.3 V18 + 2骨IK —— 当前交付版本

> 🔴 **复习重点(最容易记混的一点)**:
> 最终交付的 `smooth_fix` **不再用速度空间积分**,而是回到**位置空间**:
> `out = deskated_target + model(deskated_target, w)`
> 也就是说 §5.2 那个「速度空间突破 + FSR 3.7%」**不在最终管线里**。
> `models/v18.py` 里 `refine()` / `v18_fix()`(cumsum 路径)是**已废弃的遗留代码**,
> 与当前使用的 `deskate_xz()` / `smooth_fix()` 并存在同一个文件里 —— 读代码时极易混淆。

**三级管线**:

**① 去滑(物理)** — `models/v18.py::deskated_target`
- 接触段内:脚 XZ 固定在该段的**均值**位置(plant)
- 空中:保持原始(保留摆动形状)
- **关键:直接构造位置,不做积分 → 结构上不可能漂移**(这是对 V18 漂移问题的正解)

**② 学习式平滑器(学习)** — `models/v18.py::FootRefiner` + `smooth_fix`
- 1D 时序 CNN,4 层,hidden=64,kernel=5,**48,840 参数**
- 输入:`concat(去滑后的脚XZ, 接触权重)` = 16 维;输出:8 维位置残差
- **末层零初始化** → 残差从 0 开始 → 未训练时退化为纯去滑基线
- 训练损失(`training/v18_ik.py::SmoothLoss`):
  ```
  L = λ_jit·mean(acc²) + λ_skate·mean(|v|·w³) + λ_anch·mean(|out - deskated|)
  λ_jit=250,  λ_skate=12,  λ_anch=1
  ```

**③ 2骨IK(物理)** — `models/v18_ik.py::two_bone_ik` / `apply_ik`
对每条腿 `髋 → 膝 → 踝 (+ 刚性脚趾)`:
1. 用修正后的踝 XZ 作 IK 目标(Y 保持原始)
2. **把目标 clamp 到腿的可达范围** `|髋-踝| ≤ 大腿+小腿` ← **这一步阻止无限拉伸**
3. 余弦定理解析求膝,用原始膝确定弯曲平面(膝盖朝自然方向弯)
4. 脚趾**刚性跟随**踝:`toe_new = ankle_new + (toe-ankle)_orig` ← **修复脚掌翻转**
- 骨长**逐帧**取自原始动作 → BoneCV ≈ 原始
- 骨盆、髋、脊柱、手臂、头:**完全不动**

**最终消融(10 held-out,devlog §8)**:
```
Metric        Original  Physics  DeSk+IK  Gauss+IK  Learn+IK(交付)
FSR ↓          16.3%    11.9%     8.2%     11.1%    12.9%
Jitter ↓       0.0140   0.0319    0.0295   0.0131   0.0114   ← 全场最低
```

### 6.3 ⚠️ 一条必须记住的历史教训(会影响下一步决策)

我此前建议把 anti-skate 项换成对齐阈值的 **soft-count**(可微 FSR)。**但 V16 已经试过 soft_FSR 并且惨败**(FSR 35.8%,模型钻空子把脚甩到 25cm 外)。

两者的差别在于**约束环境**,不是损失本身:

| | V16(失败时) | 现在(V18+IK) |
|---|---|---|
| 输出自由度 | 模型直接输出全新轨迹,脚可自由跑 | 只输出**去滑目标上的残差** |
| 防漂移 | 只有一个弱 anchor 项 | anchor 项 + **IK reach clamp 硬钳制** |
| 骨架约束 | 无 | 2骨IK 强制骨长 |
| 结果 | 脚跑到 12–25cm 外 | FootErr 0.05m |

也就是说 **V16 的作弊路径(把脚甩走)现在被 IK 的可达性钳制物理性地堵死了**。所以「这次可能不一样」是有理由的——但这个理由必须显式验证(跑完看 FootErr 有没有炸),**不能默认成立**。
